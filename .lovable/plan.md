# ทำให้ PDF ที่ export ตรงกับหน้า Preview รายงานประจำปี

## ปัญหาปัจจุบัน
ไฟล์ PDF ที่ได้ ไม่เหมือนหน้า Preview เพราะโค้ดสร้าง PDF ตอนนี้:
- ถ่ายภาพแต่ละหน้าตามความกว้างจริงของกล่อง Dialog (ซึ่งเปลี่ยนไปตามขนาดจอผู้ใช้) ไม่ใช่ความกว้างกระดาษ A4 → สัดส่วนและขนาดตัวอักษรเพี้ยน
- ถ้าเนื้อหาหน้าไหนสูงเกินหน้ากระดาษ จะถูก "บีบ" ให้พอดี (`Math.min`) ทำให้ตารางยืด/ผิดสัดส่วน หรือเนื้อหาหาย
- กราฟ Recharts และฟอนต์ไทยบางส่วนอาจยังเรนเดอร์ไม่เสร็จตอนถ่ายภาพ ทำให้ PDF ได้กราฟเปล่าหรือฟอนต์ผิด

## สิ่งที่จะทำ
1. **เรนเดอร์เพื่อพิมพ์ด้วยความกว้างคงที่แบบ A4**
   ตอนกด Export PDF จะโคลนเนื้อหา Preview ไปวางในกล่องซ่อน (offscreen) ที่ตั้งความกว้างเท่ากับพื้นที่พิมพ์ A4 เสมอ แล้วค่อยถ่ายภาพ → ผลลัพธ์เหมือนกันทุกเครื่อง ไม่ขึ้นกับขนาดจอ
2. **รักษาสัดส่วนและตัดหน้าอย่างถูกต้อง**
   ถ้าหน้าใดสูงเกิน A4 จะแบ่งเป็นหลายหน้าโดยคงสัดส่วนเดิม แทนการบีบภาพ ทำให้ตาราง/ตัวเลขไม่ยืดผิดรูป
3. **รอให้ทุกอย่างพร้อมก่อนถ่ายภาพ**
   รอฟอนต์ไทย (`document.fonts.ready`) และรอให้กราฟวาดเสร็จ ก่อนเริ่มสร้าง PDF พร้อมแสดงสถานะกำลังสร้าง
4. **คุณภาพและขนาดไฟล์**
   ใช้ scale 2 และ JPEG คุณภาพสูงเหมือนเดิม เพื่อความคมชัดโดยไฟล์ไม่ใหญ่เกินไป

## ขอบเขต
แก้เฉพาะฟังก์ชันสร้าง PDF ในหน้า `/reports` (คอมโพเนนต์ Preview รายงานประจำปี) ไม่แตะสูตรคำนวณ ข้อมูล หรือหน้าอื่น ผลลัพธ์ PDF จะมีเนื้อหา ลำดับหน้า สี และตารางเหมือน Preview ทุกประการ

## รายละเอียดเชิงเทคนิค
- ใน `src/routes/_authenticated/reports.tsx` → `AnnualReportPreview.generatePDF`
- สร้าง container ซ่อน (`position: fixed; left: -10000px; width: 794px` ≈ 210mm ที่ 96dpi) แล้ว `cloneNode(true)` เนื้อหา `[data-page]` เข้าไป (กราฟ Recharts เป็น SVG จึงโคลนได้ตรง)
- `await document.fonts.ready` + หนึ่งเฟรม `requestAnimationFrame` ก่อน `html2canvas-pro`
- คำนวณ `imgH = canvas.height * imgW / canvas.width`; ถ้า `imgH > pageHeight - 20` ให้ตัดภาพเป็นช่วง ๆ ด้วย canvas ย่อยแล้ว `addPage()` ต่อกัน แทน `Math.min`
- ลบ container ซ่อนทิ้งใน `finally`
